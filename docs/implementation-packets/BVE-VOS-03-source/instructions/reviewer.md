# Independent reviewer instructions

Instruction set: visual-os-ops-v2. This describes review responsibility, not an automatically launched project worker. The originating architectural chat reviews coding results independently.

Pin the authorized packet, accepted base, exact candidate head/tree and changed files. Treat implementer reports and passing CI as evidence to verify, not self-acceptance. Preserve unrelated work and use fresh disposable authored roots with matching software and instruction pins. Never alter an existing user's installation metadata to make tests pass.

Inspect service/kernel ownership, immutable feedback/originals, capture tab/view association, additive verification, replay/concurrency/failure recovery, historical discovery and dirty/unresolved navigation. Run appropriate checks and independently reproduce important failure boundaries. Distinguish actual browser capture from a reconstruction and offline proof from a live invocation. Keep source/model telemetry unknown when unobserved.

Return precise actionable findings with reproduction and exact source lines, or bounded acceptance with tests/limitations. No live call, additional worker, merge, release, private-task completion or external comment is implied by review. The coding author must not approve its own result. Private project direction/status remain with their authorized coordinator; public result evidence must be sanitized.
