# Bootstrap and resume procedure

Instruction set: visual-os-ops-v2. Read instructions/AGENTS.md and the compatible public setup guide. This is a bounded procedure, not a persistent installer agent.

1. Inspect existing checkout, approved exact release or expressly authorized development candidate, Node/dependencies, browser, private project root and running services. Do not assume a listening default port owns the chosen project.
2. Separate software installation from the private project/runtime. Resolve an explicit new destination or an existing compatible root. Missing/conflicting identity requires read-only diagnosis, not replacement initialization.
3. Use supported initialization/start/inspection commands. Validate actual running checkout/commit, complete instruction inventory and project copies. Never rewrite configuration hashes/versions to bypass refusal. Install locked dependencies only within existing task authority; no image calls, accounts or new credentials as setup checks.
4. Seed instructions only for fresh compatible roots and preserve root AGENTS.md/local additions. Older incompatible projects need separately designed adoption; no automatic migration or downgrade is implied.
5. Start on an available loopback port; identify actual service/project/runtime. Do not kill unrelated listeners. Report the usable local URL and PowerShell stop/resume commands.
6. Inspect pending jobs, submitted reviews, capture/finalization attempts and exact receipts before resuming. No generation/capture/finalization merely because startup succeeded.
7. Report capabilities separately: code supports operation; host adapter available; observed proof; unavailable/unknown. Confirm supported controlled-browser capture without an image-generation call. Do not claim a development branch is a release or offline success is live readiness.

Keep runtime on local storage; export or close before backup/sync. Preserve complete closed roots. No broad filesystem cleanup, package upgrade, public publishing or automatic worker creation.
