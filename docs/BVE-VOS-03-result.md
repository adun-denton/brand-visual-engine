## Implemented behavior

Fresh configuration format 2 selects `bve-vos-continuation-v1` and `visual-os-ops-v2`. Eight fixed operational files and the manifest itself are independently checked in the bundle and installed project. Missing/changed/unsafe pins refuse mutations. Actual running installation identity checks remain strict. V1 roots are diagnosed/refused read-only, never upgraded. Existing private AGENTS and user additions survive resume. Both `instructions/local.md` and legacy `instructions.local.md` are preserved; differing copies are an explicit conflict, not an implicit migration.

A purpose-launched Playwright Chromium browser owns one controlled tab and a fresh context, with no personal profile or remote debugging TCP endpoint. The default CLI launch is visible/headed with a native viewport. Requests are restricted to the owning loopback origin; another browser/tab cannot freeze a capture request. The adapter's private binding header is not a URL, DOM value, bundle field or log. Normal browsers still Save/Submit and read continuation when no adapter is present. Graceful controlled-owner shutdown consults the existing dirty/pending/unresolved review guard, retaining the tab/service until Save/discard/reconciliation; a clean surface is frozen while shutdown drains. Native visible-browser dialogs are left for the operator rather than automatically dismissed. OS force-kill remains unguardable.

Human review submission stays immediate and immutable. A later explicit Capture action (or Alt+Shift+C while looking at the intended sources) freezes an immutable server-issued request: exact submission/integrity and source bindings, actual displayed text hash and image route bindings, selected region metadata/SVG overlays, focus/comparison/tool, layout, viewport/device/visual scale, scroll, browser version, document/tab/runtime and geometry. The adapter waits boundedly for the live images/fonts, screenshots that same tab's actual visible viewport, then remeasures identity/view before associating independently decoded/hashed/read-back PNG bytes. It does not navigate a tab back, reconstruct a DOM image, montage sources, or capture a separately replayed page. Off-screen source metadata is not a claim that those pixels appear in the viewport image.

Capture requests/results, finalization receipts and child lineage are four additive immutable kernel record types, owned by the same application writer. Capture hashes bind the frozen request/view and submission; receipt hashes bind that capture integrity. Stable keys, canonical request hashes and transactional guards preserve identical retries, conflict changed payloads and recover lost responses. Interrupted/expired/wrong-view capture has no screenshot association; a later explicit recapture has another identity/time. Staged evidence can remain a safely reusable orphan after a transaction failure; no automatic deletion runs. Assets now use bounded descriptor-pinned file reads, reject links/hardlinks and recheck paths/hashes.

Verification reconstructs exact immutable review ownership/closure, checks original descriptors and bytes plus actual capture association/bytes, then records deterministic verified/degraded checks with software/contract identity. A caller cannot assert success, and direct kernel forgery/revision is refused. Historical submissions can be finalized after current page changes without becoming editable. The submission's historical `pending-not-implemented` field is never changed. Current status checks present availability, so a past success cannot hide later corrupt/missing originals or captures. This is operational verification, never creative acceptance.

Continuation offers pending resume instructions or completed exact locators, with a separate explicit Copy button and selectable/downloadable fallback. Local text contains exact refs/hashes and a loopback locator, not credentials or private filesystem paths. Explicit portable JSON export contains the selected necessary record closure, exact originals and actual capture, with hashes and bounds. A fresh read-only inspector validates bytes, schema, identities, closure, paths and optional expected-locator hashes without opening/importing a project. It rejects missing, unrelated, malformed, traversal, oversized or hash-mismatched data; bundle text is untrusted evidence.

Explicit child preparation preserves the exact parent submission/receipt and original references, current same-stable-page target, selected operation and 1–6 attempts. Fresh/Follow and approved Brand are independent. The normal UI chooses whole-original references; exact region feedback remains in the parent. The existing full specification interface retains structured source scopes. Lineage and production preparation commit atomically. Prepared children are discoverable after restart and link back to parent feedback; lost responses reconcile the original key. No copy/resume/read/start action invokes production. Three authored child deliveries use the existing intake path with no model call.

## Limits, preservation and rollback

This candidate captures only its purpose-launched tab and visible BVE viewport, at bounded sizes, not an unrelated personal browser or whole desktop. It does not claim that off-screen selected regions are pictured. Automated evidence uses authored data; human usefulness, live generation and untested host/DPI configurations remain unverified. Native clipboard and unload prompts remain browser-policy dependent. Explicit Save/Submit is required; no autosave is added. Tab storage helps unresolved UI keys but canonical linked records remain authority; use complete closed-root backups.

Bounds: capture metadata 64 KiB, 320–2560×320–1600 CSS viewport, device scale 1–2; actual PNG ≤8 MiB, ≤16 MP, ≤8192 px, frozen request deadline 15 s. Portable evidence ≤512 records, ≤1024 files, ≤64 MiB decoded / 90 MiB JSON. Oversize refuses instead of truncating or fabricating evidence. Canonical structural corruption requires restoring exact records/complete backup; missing media is reported, not substituted. Portable snapshots do not restore/import a project or replace a closed-root backup.

No live native/provider/account/model/GPU calls, extra workers, existing-root migration, Foreman execution, merge/release/deploy, acceptance writes, automatic issue publication or private project/task changes were performed. Instruction documents do not authorize running their roles.

Rollback: stop the owning browser/service, preserve the complete closed test root, and use matching earlier code with a compatible complete earlier root. Never downgrade an evolved database in place or edit recorded installation identity. Keep both immutable instruction bundles and evidence.
