## User-visible changes and interfaces

The paired workspace opens by default. It supports selected alternatives, focused instructions,
exact text locks, scoped request/file downloads, validated AI intake, attached returned images,
independent reusable media, immutable manual revisions, earlier-version preview, explicit acceptance,
page/Website packages, portable page import and additive legacy conversion with a loss report.

New record kinds cross the existing kernel gate: `website-page` remains a design artifact;
`page-media` is a media resource; inference/import/migration records are work records; Website
assembly has its own type. Page dependencies are exactly its own placeable media bindings. Website
selections require exact accepted page versions. Requests freeze selected base/context/resources.
No creative action or acceptance is executed from model-generated proposed actions.

HTTP endpoints live under `/api/v1/page/*` and `/api/v1/website/*`, preserving the original local
host/origin/token/body boundary. The new schema/renderer live in the Website module; `Pages` adapts
storage and imports. Legacy schema validators/records remain. Paid production submission is disabled
before a reservation or transport, while injected offline adapters continue their retained tests.

## Scope limits and rollback

See the inference workspace guide for grammar and execution limits. Local runtime/model/hardware
selection and measurement remain outstanding. Native image files use explicit handoff; direct
arbitrary-page-slot regional editing is not integrated. Legacy conversion preserves content, original
media and basic styling but explicitly does not promise recipe/chrome/responsive visual equivalence.
The grammar uses safe declared CSS and local fonts; executable HTML, custom font binaries, video,
animation, dragging, semantic merges, hosting and booking are absent. Designer and independent
technical acceptance remain pending. The earlier draft chain is not merged or certified by this work.

Rollback keeps the draft unmerged. For exercised runtime data, close the app and restore the complete
matching-code backup. Preserve any newer root/history first. Do not open the new record types with old
code and assume compatibility; the old reader may refuse them. Existing pre-migration records and
accepted legacy export bytes remain unchanged.
