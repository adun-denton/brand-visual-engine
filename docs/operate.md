# Visual OS operator guide

Instruction set: visual-os-ops-v1. This guide distinguishes the intended loop from the current packet's implemented scope.

## Product boundary

Chat handles creative discussion. BVE stores original visual artifacts and the human's review. The Conductor chooses direction, Generators execute bounded jobs, and the Butler verifies intake and continuity. The installer is a workflow, not another agent.

Target loop: request three concepts in Chat; view them together in BVE; select, annotate and comment; submit; copy continuation; discuss in Chat; view the next iteration with history.

## Candidate scope

BVE-VOS-01 implements explicit project initialization/reopen and verified intake of three authored deliveries into the existing visual workspace. It does not implement the complete target loop, native dispatch, durable review submission, product screenshot capture or clipboard continuation. The implementer must add verified command details and observed results without changing these scope limits.

Existing visual review supports whole-image/region selection and notes. Existing request controls describe changes for a future iteration; they do not generally edit bitmap pixels. Library/export preserves whole originals under the existing contracts.

## Everyday rules

- Open the same private project configuration to resume.
- Fresh/Follow and Brand are independent. Choose an explicit 1-6 attempts for generation work; retry is manual.
- Compare/select is provisional. A separate explicit human action accepts an exact design.
- Save feedback before relying on it; submitted feedback and operational verification are separate.
- A local path in a copied instruction does not grant another chat filesystem access. Use an available authorized connector or portable bundle when necessary.
- An export is not automatically a complete backup. Keep whole closed runtime backups with matching application/instruction identity.
- Stop the owning server gracefully before closed-root backup. Never remove an unknown process merely to free a port.

## Handoff and evidence

Future complete submissions retain exact variants, notes, edits and actual rendered evidence where supported. Do not call a test screenshot a user's submitted screenshot. A missing capability must remain explicit. The application stays useful when chats end.
